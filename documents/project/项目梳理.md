# Sensory-Friendly Melbourne 项目梳理

## 项目目标

为 Melbourne CBD 的感官敏感成年人提供无需登录的步行路线比较工具。系统不是简单推荐最短路线，而是结合候选步行路线附近的人流数据，给出可解释的感官负荷等级、拥挤提醒、替代路线和附近可暂时休息的公共空间。

## 两个 Epic

### Epic 1：感官友好路线规划与实时导航

- 用户输入 Melbourne CBD 内的目的地。
- 系统返回至少一条步行路线，并用开放人流数据计算感官负荷。
- 每条路线显示 LOW / MODERATE / HIGH，不能只用颜色表达。
- 当路线负荷超过用户设置的阈值时，显示警告并推荐更平静的替代路线。
- 路线附近需要显示公共交通接入点。

### Epic 2：感官环境监测

- 对高密度人流区域显示实时提醒。
- 按需显示附近 parks、libraries、quiet public spaces。
- 使用历史小时趋势给出未来一小时的预测提醒。
- 预测必须标明依据、时间与可信度，不能描述成确定事实。

## 已锁定的 MVP 边界

必须完成：

- 公网 AWS HTTPS URL；
- 无注册、登录、用户账户或数据库；
- 目的地选择与候选步行路线；
- 基于 pedestrian data 的可解释评分；
- LOW / MODERATE / HIGH 文字等级；
- 用户阈值、拥挤警告与替代路线；
- 实时人流提醒、附近安静空间；
- 键盘、清晰焦点、非颜色提示、reduced motion 等基础无障碍能力。

进入真实验收前补齐：

- Mapbox Directions / Geocoding 真实适配器；
- City of Melbourne sensor locations、past-hour counts、hourly history 适配器；
- 导师确认的 public facilities / open-space 数据集；
- Transport Victoria 站点数据；
- 历史 baseline 生成与预测准确性记录；
- CloudWatch 告警、公开部署和完整 demo checklist。

暂时不做：

- 登录、profile、收藏或历史记录；
- RDS、EC2、微服务拆分；
- 机器学习模型；
- 社交功能或完整 turn-by-turn 导航。

## 已搭好的架构

- `code/frontend/`：React + TypeScript + Vite 单页应用，包含低刺激视觉系统、路线卡片、提醒、安静空间和 Mapbox 延迟加载边界。
- `code/backend/`：一个 Lambda 风格 API；内部按 HTTP、route service、scoring、prediction 和 data adapter 分层。
- `code/packages/contracts/`：前后端共享的请求/响应类型，减少接口漂移。
- `code/data/` 与 `code/scripts/`：历史 baseline、fallback snapshot 和离线预处理入口。
- `code/infra/`：AWS SAM/CloudFormation，包含 Lambda、API Gateway、私有 S3、CloudFront OAC 与 `/api/*` 转发。
- `documents/project/requirements-traceability.md`：逐条记录 DoD 的代码位置、当前状态与验收证据缺口。

## 当前完成度

架构阶段已完成并可本地运行。页面可在无密钥状态下通过确定性 demo 数据跑通主流程；评分、阈值推荐和预测边界有自动化测试。所有返回结果显式标为 `MOCK`，不会把演示数据误称为实时数据。

## 建议的下一阶段顺序

1. 先接 Mapbox destination search 与 walking alternatives，保留 mock fallback。
2. 接 City of Melbourne 实时人流与 sensor locations，建立数据时间戳和失败回退。
3. 完成 sensor-to-route 空间匹配并用真实分布校准 LOW / MODERATE / HIGH 阈值。
4. 锁定 quiet-space 与 public-transport 数据源，补地图图层和数据说明。
5. 生成历史 baseline，补预测准确性测试。
6. 部署到 AWS staging，完成无障碍、移动端、故障和导师 demo 验收。
